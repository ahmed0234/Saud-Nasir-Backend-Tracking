# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

One central backend that tracks leads from **three WordPress websites** (Platinum SG, Clean Master, EMG Air). Each site runs its own copy of a global JavaScript snippet that sends the site's identifier; when a visitor clicks a CTA (phone, booking, email/SMS, Elementor button) or submits a lead form, the snippet POSTs to this backend, which stores it in Neon Postgres, emails a notification, and shows everything in an analytics dashboard (`/` and `/analytics`, filterable per website from the sidebar, behind a sign-in at `/login`; leads can be deleted there, nothing else is edited). It is not a CRM. Opening the dashboard must never create events or send email.

```
WordPress site A ─┐
WordPress site B ─┼─ <site>-tracker.js ─────POST /api/cta-click──▶ SvelteKit on Vercel ──▶ Neon Postgres (cta_clicks)
WordPress site C ─┘   (fetch keepalive, text/plain)                     │                        ▲
                                                                        └─▶ Gmail SMTP email      └── dashboard / , /analytics
```

- **Production backend:** `https://fluxpoint-omega.vercel.app` (endpoint `https://fluxpoint-omega.vercel.app/api/cta-click`). Deployed by the user; we never deploy.
- **Websites live in the database** (`websites`: key, name, url, accent, platform, disabled_at, last_seen_at/url; `website_domains`: hostname without `www.`, globally unique → website_key), added and managed from the dashboard (sidebar **+**, `/websites`). Migration 0003 seeded the original three with their existing keys (`platinum-sg`, `clean-master`, `emg-air`); `cta_clicks.site` is a foreign key to `websites.key`. Never change a key once leads are stored with it; websites can be disabled (keeps everything, rejects new events) or deleted from their Settings dialog: `deleteWebsite` removes the website, its domains (ON DELETE CASCADE) and all its leads in one statement, after the user retypes its exact name (checked on the server too); its key then stops working everywhere because `touchWebsite` asks the database. Migration 0003 seeds `last_seen_at` from each original site's latest lead, since their installed snippets predate the install ping. New keys are `<name-slug>-<5 random base36>`.
- **Each lead row** (`cta_clicks`) stores `site`, `event_type` (`cta_click` | `form_submit`), `button_type` (call, sms, email, booking, button, elementor_form, fluent_form, cf7_form, wpforms_form, gravity_form, form, or a `data-cta` value), `button_text`, `form_name`, `page_url`, a generated `page_path` (route), city/state and `clicked_at`. Migration 0002 added attribution: `cta_placement` (header/footer/page, CTA clicks), `source_cta_type/text/placement/page_url/clicked_at` (the CTA a form submission is credited to), a generated `is_header_cta` (the green "Header CTA" badge) and `utm_source/medium/campaign/term/content`, `gclid`, `gbraid`, `wbraid`, `fbclid`; all null on older rows. Rows recorded before migration 0001 have null button fields; `site` is null for domains outside the three sites (2 old Ridgewell rows).
- **Site resolution in the API:** the payload's site key picks the website (payloads without one are matched by page domain). It must exist and be enabled, and `pageUrl`'s host and the `Origin` (when sent) must be one of _that_ website's domains, else 403. Checked against the in-memory registry (`src/lib/server/websites.ts`: 60 s TTL, refreshed on a miss at most every 5 s and immediately on the instance that changes a website). Before a lead is inserted, `touchWebsite` re-checks enabled + domain in the database (so disabling is immediate on every instance) and records last-seen.

| ------------ | -------------- | ------------------------------- | --------------------------------------- |

| Clean Master | `clean-master` | `cleanmastercarpetcleaning.com` | CTAs are `tel:` and Housecall Pro links |

### The tracker (`src/lib/tracker/tracker.js`)

One script for every website, served publicly as **`/t.js`** (`src/routes/t.js/+server.ts`, cached 5 min) and installed with `<script src="https://<backend>/t.js" data-site="SITE_KEY" defer></script>` (WPCode → HTML Snippet → Site Wide Footer, or before `</body>`, or a GTM Custom HTML tag). It reads its site key from `data-site` and posts to `/api/cta-click` on the script's own origin. The dashboard's "full code" fallback is the same file with `var INLINE_CONFIG = null;` replaced by `{ site, endpoint }` (`src/lib/server/tracker-script.ts`, served behind sign-in at `/websites/[key]/tracker.js`); don't change that line. The old per-site files in `code-snippet-wordpress/` are gone; already-installed copies keep working (same payload, same `window.__cmCtaTracker` guard, so an old and a new copy never both send). Plain browser JS, strictly ES5 syntax (also runs as a GTM Custom HTML tag; check with `npx acorn --ecma5 src/lib/tracker/tracker.js`), linted, `@ts-nocheck` for svelte-check. Once a day per browser it sends `eventType: 'ping'` (not stored as a lead) so the dashboard shows "Waiting for installation" vs "Active · seen …".

- **Lead actions** (`eventType: 'cta_click'`, recorded as leads): `tel:` → call, `sms:` → sms, `mailto:` → email, `*.housecallpro.com` / `hcp-button` / `HCPWidget` → booking. One lead per action (type + normalized destination) per 10s, so sticky-header copies and double taps don't duplicate. Icon-only links fall back to the number/address as label.
- **Genuine CTAs that lead to a form** ("Book Now" → /contact, "Get a Quote", "Request A Bid") are _not_ leads: the last one clicked is kept in `localStorage` (`leadTracker:cta`, 30 min, shared across pages/tabs of the origin) and sent as `source` with the next form submission. A CTA = something button-styled (Elementor/add-on buttons, `.wp-block-button__link`, `<button>`, `role=button`, a class word btn/button/cta/pill) that goes to a same-site lead page/anchor (`LEAD_DESTINATION`: contact, quote, estimate, book, schedule, appointment, consult, request, bid, ...) or whose label matches `LEAD_LABEL`, label ≤ 40 chars, not matching `NOT_LEAD_LABEL` (learn, about, explore, view, apply, join, career, review, ...), not inside a form. Plain menu/text links are ignored. Overrides (CSS classes so Elementor's Advanced → CSS Classes works on the widget wrapper): `lead-cta`, `header-cta` (also forces header), `no-lead-cta`; legacy `data-cta`, `data-cta-ignore`, `data-cta-placement`.
- **Placement**: header = inside `header`/`[role=banner]`/Elementor header/`#masthead`/`.site-header`/`.topbar`, a known mobile/off-canvas menu, a popup containing a nav menu, or a bare `<nav>` near the top / fixed (Platinum's static `nav.main`); footer = footer elements; else page (incl. Platinum's sticky bottom call bar).
- **Campaigns**: `utm_*`, `gclid`, `gbraid`, `wbraid`, `fbclid` from the landing URL are stored in `localStorage` (`leadTracker:campaign`, 90 days; a newer campaign visit replaces them) and sent as `attribution` with every lead.
- **Form submissions** (`eventType: 'form_submit'`) are recorded on the `submit` event (submit button click, Enter, mobile "Go"), plus a fallback after a submit-button click for plugins that cancel the click and send via AJAX. Only filled-in forms count: HTML validity plus `aria-required="true"` fields (how Fluent Forms marks required fields). One record per form per 3s. Search, login, comment and WooCommerce forms are skipped. Field values are never sent, only the submit button label and the form name.
- One capture-phase `click` + `submit` listener on `document` (+ middle-click `auxclick`); never `preventDefault`/`stopPropagation`.
- **Transport:** `fetch(..., { keepalive: true })` with a `text/plain` JSON body (no CORS preflight, survives navigation). `navigator.sendBeacon` is only a fallback: browsers type beacons as `ping`, and EasyPrivacy's `*$ping,third-party` rule blocks them → `net::ERR_BLOCKED_BY_CLIENT`. Don't switch back to sendBeacon-first.
- Skips the Elementor editor (`?elementor-preview=`) and `/wp-admin/`. **Debug:** `?cta_debug=1` logs e.g. `elementor_form submission sent via fetch`.
- Caching/optimization plugins must not delay it (exclude from WP Rocket/LiteSpeed "delay JS"); clear caches after updating it.
- Detection rules verified 2026-10-30 against the live sites in headless Chrome (desktop + iPhone, tracking requests intercepted): header/footer/page placement, ignored nav/About/Learn More/Apply buttons, dedupe, cross-page attribution (incl. Platinum static homepage → WordPress contact form), UTM/click-ID carry-over.
- **Platinum** has static `.html` pages (homepage, `contact.html`, `about.html`, ...) with a `.topbar` + `nav.main` header, and WordPress pages (`header#masthead`, `/contact-us/`, `/blog/...`); same origin, so `localStorage` attribution carries between them. Both load GTM container `GTM-NPFS2VJD`, so the static pages can get the tracker as a GTM Custom HTML tag (no file access); WPCode only reaches the WordPress pages.

## Commands

Package manager is **bun** (`bun.lock`); `.npmrc` sets `engine-strict=true`.

- `bun install` — install deps (runs `svelte-kit sync` via `prepare`)
- `bun run dev` — dev server
- `bun run build` / `bun run preview` — production build (Vercel adapter) and local preview
- `bun run check` — `svelte-kit sync` + `svelte-check` type checking
- `bun run lint` — `prettier --check .` then `eslint .`
- `bun run format` — `prettier --write .`
- `bun run db:generate` — generate a SQL migration in `drizzle/` from schema changes
- `bun run db:migrate` — apply pending migrations to the database at `DATABASE_URL`
- `bun run db:studio` — Drizzle Studio

`drizzle.config.ts` loads `.env` via `dotenv`. On Windows, `bun run build` fails at the Vercel adapter step (symlink EPERM) unless Developer Mode is on; the Vite compile before that step is still a valid check.

No test framework is configured.

## Stack specifics worth knowing

These differ from older SvelteKit conventions, so don't assume SvelteKit 2 patterns:

- **SvelteKit 3 / Svelte 5 / Vite 8.** There is no `svelte.config.js` — SvelteKit config (adapter, compiler options) lives inside the `sveltekit({...})` plugin call in `vite.config.ts`.
- **Runes mode is forced** for all project files (`compilerOptions.runes` in `vite.config.ts`). Use `$props()`, `$state()`, `$derived()`, `{@render children()}` — not `export let`, `$:`, or `<slot>`.
- **`#lib` instead of `$lib`.** The lib alias is a Node subpath import defined in `package.json` `imports` (`#lib` → `src/lib/index.js`, `#lib/*` → `src/lib/*`), e.g. `import favicon from '#lib/assets/favicon.svg'`.
- `tsconfig.json` extends `$app/tsconfig` (generated by `svelte-kit sync`); run `bun run check` or `svelte-kit sync` if generated `./$types` imports fail to resolve.
- **Tailwind CSS v4** with no `tailwind.config.*`: configuration and plugins (`@tailwindcss/forms`, `@tailwindcss/typography`) are declared in `src/routes/layout.css`, which is imported by the root `+layout.svelte`. Prettier's Tailwind plugin also points at this file for class sorting.
- `@sveltejs/enhanced-img` is enabled for optimized images.
- Deploy target is Vercel (`@sveltejs/adapter-vercel`).

## Architecture

- **Env vars** are declared in `src/env.ts` with `defineEnvVars` (SvelteKit 3's replacement for `$env/*`) and imported from `$app/env/private`. The `AUTH_*` vars are deliberately optional (null when missing) so a missing value can't take the tracking endpoint down. Allowed tracking origins are not env vars: they come from the website registry.
- **Auth:** single account from `AUTH_USERNAME`/`AUTH_PASSWORD`, checked only on the server (`src/lib/server/auth.ts`, constant-time). `src/hooks.server.ts` protects every route except `PUBLIC_ROUTES` (`/login`, `/logout`, `/api/cta-click`, `/t.js`; the tracking endpoint and script must stay public). Unauthenticated page and data requests get a 303 to `/login?redirectTo=…` (validated same-origin only); other requests get 401. Sessions are stateless: an HMAC-signed `v1.<expiry>.<sig>` cookie (`__Host-session` on HTTPS, `session` on http dev; httpOnly, SameSite=Lax, 7 days), signed with a key derived from `AUTH_SECRET` + the credentials, so changing either signs everyone out. Sign-in is rate limited (10 per IP per 15 min, per instance) and same-origin only, like `/logout` (POST). The login page (`src/routes/login`) plays a CSS opening animation while `preloadData` loads the dashboard, then `goto`s; it falls back to a full page load if that fails. Every full load of the dashboard (open, reload, and right after sign-in, continuing the login veil) plays `#lib/components/dashboard/opening-intro.svelte`: server-rendered, CSS-only (transform/opacity), ~0.9s, never replays on client-side navigation, hidden under `prefers-reduced-motion`.
- **Database:** Drizzle ORM over Neon's HTTP driver (`drizzle-orm/neon-http`). Client in `src/lib/server/db/index.ts`, schema in `src/lib/server/db/schema.ts`. Drizzle Kit owns migrations in `drizzle/` (excluded from Prettier). Don't introduce Prisma.
- **Endpoint:** `POST /api/cta-click` (`src/routes/api/cta-click/+server.ts`) accepts `{ site?, eventType?, buttonType?, buttonText?, formName?, pageUrl, city?, state?, clickedAt?, placement?, source?, attribution? }` (body ≤ 8 KB). Attribution fields are best effort: invalid values are dropped to null, never rejecting the lead; `source` only applies to form submissions and only if clicked ≤ 35 min before and naming a type, text or placement; click IDs must be URL-safe tokens. Who may send is decided by the website registry (see Site resolution above); `eventType: 'ping'` only updates last-seen. Rate limits per instance: 30 leads/min per IP, 300 leads/min per website, 60 pings/min per IP. CORS headers are only sent for origins registered to an enabled website (they are not the security boundary). Missing city/state fall back to edge geo headers (`src/lib/server/geo.ts`: Vercel `x-vercel-ip-*`, Cloudflare `cf-*` fallback); a missing or implausible `clickedAt` falls back to server time. The body is parsed as JSON regardless of content type, so the snippet's `text/plain` requests (no CORS preflight) work; replies 204 on success, 400/403/405/413/429 otherwise.
- **Email:** after the insert, the endpoint returns 204 and sends a notification via `waitUntil` from `@vercel/functions` (a no-op outside Vercel). `src/lib/server/email/index.ts` sends through Gmail SMTP (Nodemailer 10, which ships its own types) and never throws; on Gmail quota/rate-limit/auth errors it pauses sending per instance. The HTML template lives in `src/lib/server/email/cta-click-email.ts` and must escape every interpolated value.
- **Production hardening:** `src/hooks.server.ts` sets security headers (nosniff, `X-Frame-Options: DENY`, `X-Robots-Tag: noindex`); `/api/cta-click` is rate limited (`src/lib/server/rate-limit.ts`, in-memory, per instance, best-effort). `vite.config.ts` sets `maxDuration: 60` on the Vercel function. `package.json` pins Node `24.x` (Vercel otherwise builds on the newest Node, which the adapter rejects) and `vite.config.ts` pins the `nodejs24.x` function runtime.
- **CSRF:** SvelteKit's built-in origin check is off (`csrf.trustedOrigins: ['*']` in `vite.config.ts`; `checkOrigin` no longer exists in SvelteKit 3) because tracked websites are only known at runtime. Instead `hooks.server.ts` rejects (403) every POST/PUT/PATCH/DELETE whose `Origin` isn't the app's own, except `/api/cta-click`. This covers all form actions, sign-in and sign-out, also in dev and for JSON bodies. Keep new state-changing endpoints behind it.
- **Routes:** the dashboard lives in the `src/routes/(app)` group (its layout loads `getSiteCounts`, the websites (fresh, not cached) and `trackerOrigin` for install codes; pages read them via `data` / `page.data`, typed in `app.d.ts`); the root layout only sets up theme, toasts and the time-zone cookie, so `/login` renders without the shell. In SvelteKit 3, `resolve()` takes a route ID (leading `/`, e.g. `resolve('/(app)/analytics')`) or a pathname (no leading slash). **Links with a query string must use the pathname form** (`resolve(`?${params}`)`, `resolve(`analytics?${params}`)`): the route-ID form only drops the `(app)` group when it is a whole segment, so `resolve('/(app)?site=x')` produced `/(app)?site=x`, which 404s. `route.id` is `'/(app)/analytics'`.
- **Dashboard:** the `(app)` layout has a glass sidebar (`#lib/components/dashboard/app-sidebar.svelte`; a Sheet below `lg`) listing All websites + the three sites with all-time counts (`getSiteCounts` in `(app)/+layout.server.ts`) and a sign-out button. The selected site lives in the `site` URL param; every analytics query takes it (`null` = all). Server `load` functions (no client-side DB access) call `src/lib/server/analytics.ts`, which does all aggregation in Postgres. `/analytics` filters live in URL params (`range=24h|3d|7d|30d|custom&from&to`). Time-series buckets come from `generate_series`, so empty periods are zero. UI uses the shadcn-svelte components in `src/lib/components/ui`, layerchart 2 via `ui/chart`, and app components in `src/lib/components/dashboard`; the `glass` surface utility is defined in `layout.css`. **View transitions** (CSS only, `.dashboard-view` in `layout.css`): when the page or website changes (not filters), the `(app)` layout's `{#key}` remounts the view; while the next one loads it gets `data-leaving` (dims), then its sections and the children of any `data-stagger` element rise in. The sidebar highlights (sites and views) move on click via `navigating.to`, while `aria-current` stays on the page actually shown.
- **Time zones:** timestamps are stored and sent as UTC ISO strings. `+layout.svelte` writes the browser's IANA zone to the `tz` cookie (`src/lib/timezone.ts`) and refreshes once; server loads use it for local-day boundaries (`AT TIME ZONE`) and pass `timeZone` to pages so server and client format dates identically. In SQL, parenthesize `x` in `x AT TIME ZONE tz` when `x` is an expression.
- **Test email:** the `sendTestEmail` form action on `/` calls `sendTestEmail()` from the email module, throttled to one per 30s per instance.
- **Deleting leads** (permanent, `src/lib/server/delete-leads.ts`): the `deleteLeads` action on `/` takes repeated `id` fields (row trash button, checkbox selection, "Select all" = the rows shown, max 200 ids); the `deleteRange` action on `/analytics` takes the page's exact `start`/`end` instants (end capped at `loadedAt`, so a range ending today never takes leads that arrived after the page loaded) plus `site` (empty = all). Both are same-origin only and go through `confirm-delete-dialog.svelte`; on success the page calls `showDeleted()` (the centre pop in `deleted-pop.svelte`, mounted once in the `(app)` layout) and `refreshAll()`. Actions are posted to `?/name`, which drops the page's query string, so call `refreshAll()` rather than enhance's `update()` (it would navigate to the action location and lose `?site=`).
- **CSV export:** the green "Export CSV" button on `/analytics` (`export-csv-button.svelte`) fetches `GET /analytics/export?start&end[&site]` (`(app)/analytics/export/+server.ts`, behind sign-in) with the same `start`/`shownEnd` instants as `deleteRange`, so the file holds exactly the leads counted on screen, oldest first. `src/lib/server/export-leads.ts` writes RFC 4180 CSV by hand (no library): UTF-8 BOM, CRLF, client-facing column names, local date/time in the viewer's `tz` plus UTC, and an apostrophe before values starting with `= + - @` (CSV injection; lead text comes from public sites). The response's `x-lead-count` header feeds the success toast.
- **Browser info is not stored.** The schema has no browser/user-agent column; the endpoint only forwards the `User-Agent` header to the email.
- `page_path` is a Postgres generated column (`generatedAlwaysAs` in the schema), so it can't drift from `page_url`.
- SvelteKit 3: use `refreshAll` (not `invalidateAll`), `goto(url, { reset: false })` (not `noScroll`/`keepFocus`), and `resolve()` from `$app/paths` for internal links (ESLint enforces it; external WordPress links need an eslint-disable block).
- `#lib/*` subpath imports need explicit file extensions (e.g. `#lib/server/geo.ts`).

## Code style

Prettier: tabs, single quotes, no trailing commas, print width 100. ESLint uses typescript-eslint + eslint-plugin-svelte with `no-undef` disabled and `_`-prefixed args allowed; it respects `.gitignore` and skips `.agents/` and `.claude/` (agent skill bundles, also in `.prettierignore`). `bun run lint` passes cleanly; keep it that way.
